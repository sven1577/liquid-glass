## 2026-08-03 - Reuse Shared Canvas, Map Caching, and Radius Caching in Liquid Glass
**Learning:** Frequent window resize/drag animations can trigger intensive canvas operations (`makeMap` creating a new `<canvas>`, executing complex vector gradient fills, and doing `toDataURL` serialization) on every animation frame or throttle tick, leading to high garbage collection pressure and main-thread lag. Additionally, querying computed styles frequently for corner radius causes synchronous layout calculation/thrashing.
**Action:** Share a single static `<canvas>` across all instances to prevent canvas GC pressure; cache generated dataURIs in an LRU/LRU-like cache keyed by dimensions and styling parameters to avoid duplicate costly CPU operations; and cache parsed border radius values using a `WeakMap` style cache to prevent unnecessary computed style queries.
