## 2025-02-15 - Canvas/DataURL Caching and Element Dimension Early-Bypass
**Learning:** In highly interactive visual effects libraries (such as liquid-glass.js, which uses `canvas.toDataURL()` to generate SVG displacement maps dynamically on resize or movement), two primary bottlenecks can severely affect frame rate and CPU usage:
1. Dynamic, frequent canvas and 2D context allocation leads to heavy garbage collection (GC) pressure. Reusing a single, module-level canvas/context object completely eliminates this.
2. In active element interaction (like dragging), position changes invoke layout triggers or custom update routines (`refresh()`). However, if the element's actual dimensions (`offsetWidth`/`offsetHeight`) and style-based properties (like `border-radius`) do not change, regenerating the base64-encoded displacement map is completely redundant. Storing and comparing these properties as instance properties allows an early escape that completely bypasses canvas rendering and expensive DOM updates.
3. For scenarios where dimensions change but repeat (e.g. oscillating scaling, standard preset sizes, or snapping actions), using an LRU map cache for `toDataURL()` results saves CPU cycles by avoiding slow, synchronous pixel extraction.

**Action:** Always reuse a module-level shared canvas and context for auxiliary image/pattern generations instead of allocating a new canvas per invocation. Implement instance-level tracking of layout-relevant dimensions (`w`, `h`, `radius`) to early-exit from map generation routines if no physical resizing occurred. For dynamic resizing/scaling that is bound to repeat, cache the generated base64 strings in a size-capped LRU map cache.
