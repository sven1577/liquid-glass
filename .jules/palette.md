## 2025-02-14 - Accessible Draggable Components and Custom Switch Controls
**Learning:** Custom interactive components like floating draggable widgets must be fully keyboard navigable with clear visual indicators. Simply making custom switch tracks checkable doesn't provide focus unless adjacent sibling selectors are paired with `:focus-visible` (e.g., `input:focus-visible + .switch-track`). For draggable components, mapping keyboard Arrow keys to target physics variables (like `tx`/`ty`) creates a delightful, accessible, and physics-consistent movement experience that matches mouse/pointer gestures perfectly.
**Action:** When designing complex custom interactive components, always include `:focus-visible` outlines on parent containers and all interactive elements. Map standard Arrow keys (with Shift modifiers for accelerated steps) to control any drag/move operations, keeping keyboard users fully in sync with standard drag-and-drop or positioning behavior.
