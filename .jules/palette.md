## 2026-10-15 - Child Focus Target Guards for Interactive Container Widgets
**Learning:** When adding keyboard navigation handlers (such as Arrow key movement) to interactive container components (`tabindex="0"`), keyboard events originating from child controls (inputs, switches, buttons) will bubble up and trigger unintended physics target movements unless `e.target !== containerElement` is checked. Additionally, checking for custom styled toggle focus via `:focus-visible` on the underlying input connected to sibling switch tracks is essential for screen reader / keyboard focus visibility.
**Action:** Always check `e.target !== containerElement` on keydown handlers for container widgets with interactive children, and pair hidden checkbox inputs with `:focus-visible` adjacent sibling CSS rules.
